How I build

Two control planes I walk through on a whiteboard.

Hover a step. The point is the loop — not a chatbot demo.

Voice assistant harness

Custom spoken agent: listen, remember, act in the background, speak, continue.

  1. STT. Stream audio. The session starts when the mic opens.
  2. Transcribe. Structure the text. Separate commands from conversation.
  3. Memory. Write facts, tasks, and preferences from both commands and talk.
  4. IDs. One conversation_id. A new turn_id each exchange.
  5. Actions. Tools and jobs run off the speech path.
  6. Response. Ground the answer in memory and tool output before speech.
  7. TTS + continue. Speak, then stay in the loop. Orchestration owns state and recovery.

AI governance and execution engine

Same discipline as Prompt Studio: policy first, then a plan, then a logged run.

  1. Intake. Name the job, data class, and blast radius first.
  2. Policy. Bind allowed models, tools, stores, and spend.
  3. Risk. Escalate PII, regulated, or irreversible actions.
  4. Plan. Compile the execution DAG and the definition of done.
  5. Execute. Least-privilege tools. No wandering agents.
  6. Review. High-risk steps need a named owner. Silence is not approval.
  7. Audit. Prompts, tools, and decisions share IDs so any run can be replayed.
