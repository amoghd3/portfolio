Document processor

Large-document intake reduced to a minimized reasoning set. That set drives a standard output document, human-in-the-loop review, a full-step audit log, and selective RAG for later agent work.

Bring in the PDFs, spreadsheets, and other source files.

How it was built

Intake reduces large PDFs and spreadsheets to a smaller working set so the model can reason over them. That set drives a standard output document. A person reviews it before it ships.

How it scaled

Every intake and generation step writes an audit log. The same store can be used as selective RAG when an agent needs the data later.

Key features

Document intake, minimized reasoning set, standard generation, human approval, full-step audit, and selective RAG handoff.

  1. Bring in the PDFs, spreadsheets, and other source files.
  2. Cut them down to a working set the model can reason over.
  3. Store that set so later steps use the same facts.
  4. Reason over the reduced set.
  5. Generate a standard output document.
  6. A person reviews and approves before it ships.
  7. Log intake and creation at every step.
  8. Use the store as selective RAG when an agent needs the data.

Ducky AI

Governed RFx generation in Excel. A VBA harness calls the model, runs the returned code on the sheet, and writes the result back. That is how I drafted, acted on, and executed RFx work cheaper and faster. 90% faster creation.

Load the RFx set the team already has.

How it was built

Ducky AI ran in Excel. I put the RFx corpus behind a natural-language query. A VBA macro sent sheet context to an AI API, executed the returned code, and wrote results into the workbook. A person edited before the package left.

How it scaled

Draft time dropped 90 percent. The same harness let the team act on RFx data in the sheet, cheaper and faster. Salesforce reporting on 200+ demos a month cut validation time 83 percent.

Key features

Governed corpus query, VBA execution harness, in-sheet results on RFx data, human review gate, and Salesforce-backed validation.

  1. Load the RFx set the team already has.
  2. Ask for a section or an action in ordinary language.
  3. The model writes the first pass.
  4. VBA sends sheet context to the API.
  5. The macro runs the returned code in Excel.
  6. Results land in the workbook. That is the action on the RFx data.
  7. A person edits before it leaves the building.
  8. Creation time dropped 90 percent. Execution stayed in the sheet, cheaper and faster.

Two reference architectures I can walk through. Click a step for the short version.

Voice assistant harness

A spoken agent that keeps conversation state, assigns thread and turn IDs, and runs tools in the background while it talks.

Audio streams in as soon as the mic opens.

  1. Audio streams in as soon as the mic opens.
  2. Clean the text and split commands from ordinary talk.
  3. Write facts, tasks, and preferences from both.
  4. One conversation_id for the thread. A new turn_id each exchange.
  5. Tools and jobs run without holding the speech path.
  6. The answer uses memory and tool output, then TTS speaks.
  7. Orchestration keeps IDs, memory, and retries for the next turn.

AI governance and execution engine

How I would run model calls in a bank: policy and risk first, then a planned execution path, then an evidence bus you can replay or stop.

Name the job, the data class, and who gets hit if it fails.

  1. Name the job, the data class, and who gets hit if it fails.
  2. Bind the models, tools, stores, and spend that are allowed.
  3. Escalate PII, regulated work, or irreversible writes.
  4. Write the step order and what done means.
  5. Tools run with the least access they need.
  6. High-risk steps wait for a named owner.
  7. Prompts, tools, and decisions share IDs so you can replay the run.
